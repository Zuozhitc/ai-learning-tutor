# AI 基础概念学习辅导

状态：模型无关教学框架 v0。已实现检索与可回放的教学流程内核，保留内部生成契约；没有真实模型服务或最终用户界面。

项目主页：[Zuozhitc/ai-learning-tutor](https://github.com/Zuozhitc/ai-learning-tutor)。后续进展持续更新到本仓库。

这是一个以 AI 产品经理实践为目标的个人项目。参考已有教学产品的形态，从一个小学习场景开始，逐步完成问题验证、需求定义、原型、验收、试用和迭代。

## 已确定

- 面向学习者提供辅导。
- 内容方向确定为 AI 基础概念；项目发起者也将作为首位试用者参与操作。
- 首个知识单元确定为分类、回归与聚类，重点连接实际问题、任务选择、数字含义和结果应用。
- 项目资料以公开 GitHub 仓库持续展示。
- 首个项目优先保证过程清晰、范围可控和结果可验证，不以原创产品形态为前提。
- 以学习者能否独立完成目标任务来验证价值，具体方法与标准待定义。
- 记录人和 AI 的分工，以及假设、决策、失败、验证结果与版本变化。

## 尚未确定

- 学习者人群与使用情境。
- 首个单元的最终范围与教学流程；已收集概率、阈值、预测值及评估指标等历史疑问。
- 发起者之外可接触的试用者及需求证据。
- 第一版功能范围、技术方案、时间与成本预算。
- 正式名称及上线方式。

## 拟议推进路径

| 阶段 | 核心问题 | 对应产物 | 进入下一阶段的依据 |
| --- | --- | --- | --- |
| 1. 场景与问题 | 谁在学什么，卡在哪里，现在怎么解决？ | 场景说明、访谈或观察记录 | 有具体实例支持问题，而非只凭想象 |
| 2. 范围与目标 | 第一版帮助完成什么，哪些需求暂缓？ | 一页需求、优先级、成功标准 | 核心任务及完成条件明确 |
| 3. 辅导流程与方案 | 如何澄清、提示、练习、纠错和检查理解？ | PRD、交互流程、方案比较 | 能依据流程演练正常与失败情境 |
| 4. 原型与验证 | 是否能按预期运行并给出可靠辅导？ | 原型、用例、评测结果、失败案例 | 达到事先定义的质量门槛 |
| 5. 真实试用 | 用户是否会用，是否能独立完成目标任务？ | 试用记录、任务结果和反馈 | 如实呈现有效与无效部分，小样本不外推 |
| 6. 版本迭代 | 修改什么，为什么，修改后有没有改善？ | 版本对比、回归结果和复盘 | 用证据解释取舍与变化 |

以上是拟议路径，不代表对应工作已经完成。阶段随需求证据调整，不预设必须使用 RAG 或 Agent。

## 回放教学流程

8B仅为受限模型设计假设，尚未选型。应用内部保留生成契约，不提供服务地址、密钥或模型选择界面。以Codex手动填写请求/响应和固定样例先验证框架。

```powershell
python -m tutor_rag.workflow demo --out output/framework-demo.json
python -m unittest discover -s tests -v
```

已完成25项测试，以及包含补充重答、支线暂存、暂停恢复的合成回放。固定样例与Codex手动走查不代表真实8B能力或真实用户学习效果。详细操作见[框架说明](docs/framework.md)。

## 运行检索原型

Python 3.10+，无需安装额外依赖；在项目目录执行：

```powershell
python -m tutor_rag search "分类输出0.7的概率，为什么不叫回归？"
python -m tutor_rag search "想预估他下个月花多少钱，这要什么任务？" --mode concept-bm25
python -m tutor_rag prompt "分类输出概率为什么不是回归？"
python -m tutor_rag evaluate --out reports/retrieval-v0
python -m unittest discover -s tests -v
```

默认 BM25，概念增强版供对照。search 展示教材候选与官方来源，prompt 导出准备交给模型的上下文，**二者均不生成答案**。当前有11张教学卡、6个来源记录，内容为AI对照来源整理的初稿。小诊断集中BM25为12/13题找到前三位相关卡，增强版为13/13，但增强版对4个无支持问题中的2个也返回候选。结果不是独立盲测或教学效果验证。
