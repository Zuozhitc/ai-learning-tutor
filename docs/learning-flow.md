# 关联概念辅导流程草案

创建日期：2026-10-22；更新日期：2026-10-23。已确认首位学习者偏好在一段讲解后统一确认理解。当前已实现相应阶段内核并做合成回放，尚未实现最终界面或开展真实学习者试用。见[框架说明](framework.md)。

## 设计依据

首位学习者自述：解释会引出新问题，关联概念可能被 AI 带过，需要自己找到关键点再追问。产品尝试主动说明关联，并让理解缺口有机会显露；不假设 AI 能直接读取真实理解状态。

随后学习者明确选择在讲解结束后统一确认理解：担心中途插入问题或新知识点，再不断展开关联概念，会导致原问题尚未理解就忘记最初目标。这是首位学习者的偏好和担忧，尚不是普遍学习规律或效果验证结论。

## 本轮默认交互原则

- 每轮围绕一个明确的小目标，讲完一段连贯解释后，再统一确认理解；不在关键转折中自动插入测验。
- “一段”按一个小目标组织，不等于一次灌输整门课程；具体长度与节奏在试用中调整。
- 仍然在讲解中解释概念关联，但说明关联不等于立刻开启新知识分支或要求用户回答。
- 用户可以随时主动打断澄清。下面的延后机制是助手提出的方案，不把用户锁在不能提问的流程中。

## 一段拟议交互

| 环节 | 学习者看到或可以做什么 | 设计目的 |
| --- | --- | --- |
| 本轮目标 | 清楚展示本轮只要弄清的一个问题，沿用一个短业务案例 | 保持任务范围明确 |
| 连贯讲解 | 围绕目标讲完一小段，交代必要关联及例子之间的对应关系，中途不自动插题 | 避免被动打断及概念分支蔓延 |
| 衍生问题暂存 | 对非必要扩展先用简短文字记入待处理问题，讲解主线保持不变 | 保留疑问，避免立即开启另一课 |
| 用户主动澄清 | 学习者可以随时提问；默认优先解释与本轮目标直接相关的卡点 | 不限制学习者主动求助 |
| 段末统一确认 | 讲解结束后，以简短复述或一个新例子检查本轮目标；允许表示不清楚、继续讲解或跳过 | 在完整语境下寻找理解线索 |
| 定位与补充 | 根据回答提出可能缺口，允许用户纠正；一次围绕一个必要缺口补充，补完再统一确认 | 避免因补充不断产生新的学习目标 |
| 主线收束 | 总结本轮目标、已经展示的表现和仍不确定的部分 | 确认原问题是否已处理 |
| 选择后续 | 列出尚未解决的衍生问题，让学习者选择继续哪个或结束；不默认自动依次讲完 | 保持下一轮目标可控 |

如发现理解当前目标必需的前置概念确实缺失，应明确说明关系，缩小本轮范围或先补该概念，再回到原问题；不把必需的内容一律延后。该处理方式仍待试用验证。

表中为拟议交互示意，不是已经核验完成的教材或正式题目。

## 首版观察重点

- 用户能否更容易指出或确认卡点；AI 误判卡点时能否纠正。
- 例子之间的对应关系是否清楚，是否仍有关键跳步。
- 段末确认是否仍过长或过密，一段讲解的长度是否合适；用户为何选择跳过。
- 衍生问题暂存是否确实保留疑问，是否误把理解当前目标必需的内容延后。
- 衍生问题处理后是否能回到原任务；未解决的问题是否被保留。
- 用户是否能独立处理新例子，以及哪些步骤仍依赖提示。

不把更少提问、更快学完或更高满意度直接等同于学会。具体测量方式及标准待定义。
