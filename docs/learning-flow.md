# 关联概念辅导流程草案

日期：2026-10-22。状态：交互假设，供讨论；尚未实现或试用。

## 设计依据

首位学习者自述：解释会引出新问题，关联概念可能被 AI 带过，需要自己找到关键点再追问。产品尝试主动说明关联，并让理解缺口有机会显露；不假设 AI 能直接读取真实理解状态。

## 一段拟议交互

| 环节 | 学习者看到或可以做什么 | 设计目的 |
| --- | --- | --- |
| 本轮目标 | 今天用一个客户购买案例练习解释模型输出，并说明如何使用结果 | 保持任务范围明确 |
| 当前概念 | AI 先围绕当前问题给一小段解释，列出当前需要用到的概念 | 避免术语突然出现 |
| 引入关联 | 引入“阈值”前，先说明本轮为何需要从模型输出讨论到一个决策规则，并沿用同一个案例 | 解释概念之间的桥梁 |
| 轻量确认 | 请学习者用自己的话说明两个步骤的关系，或解释一个小例子；也可以选择“这一步还不清楚”或跳过 | 提供理解线索，降低组织疑问的负担 |
| 定位缺口 | AI 根据回答指出可能需要澄清的地方，允许用户纠正这个判断 | 将诊断视为假设 |
| 补充关联 | 一次补一个关联，使用更小的例子或前置解释；可以查看前后两个例子的对应关系 | 避免重复长解释或连续引入更多术语 |
| 衍生追问 | 学习者可以随时追问；界面保留原问题和当前暂停步骤 | 允许支线探索 |
| 回到主任务 | 补充结束后简短说明解决了什么、还有什么不确定，再继续原练习 | 避免支线吞没主线 |
| 独立应用 | 用未讲过的新案例说明结果含义及其用途，帮助和提示分别记录 | 检查可迁移的应用表现 |

表中为拟议交互示意，不是已经核验完成的教材或正式题目。

## 首版观察重点

- 用户能否更容易指出或确认卡点；AI 误判卡点时能否纠正。
- 例子之间的对应关系是否清楚，是否仍有关键跳步。
- 理解确认是否过密，是否干扰学习；用户为何选择跳过。
- 衍生问题处理后是否能回到原任务；未解决的问题是否被保留。
- 用户是否能独立处理新例子，以及哪些步骤仍依赖提示。

不把更少提问、更快学完或更高满意度直接等同于学会。具体测量方式及标准待定义。
