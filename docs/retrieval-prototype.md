# 检索原型 v0：小项目先用什么方式

日期：2026-10-22。已实现教材检索、上下文组装与离线诊断；**未接入生成模型，不是完整 RAG 问答系统**。

## 当前可运行内容

- Python 3.10+，只使用标准库，无需安装包、注册服务、输入密钥或下载模型。
- 11 张中文概念与关联卡，6 个官方来源记录。内容为 AI 独立整理并对照来源核验的初稿，尚未经领域专家审阅或真实学习者验证。
- 按完整概念卡建立内存索引，避免固定字符切块截断一个解释。当前规模不需要单独部署数据库。
- 检索输出候选卡、匹配词、匹配概念、原文和来源。分数是排序分数，不是置信度。
- 可导出带课程小目标、完整候选材料和来源的 messages JSON，后续可接模型；现在没有任何模型生成的答案。
- 索引只读取 kb/cards.json，来源与别名分别来自 kb/sources.json 和 kb/concepts.json。诊断题、相关性标注、项目 memory 不入库。

## 本轮比较与取舍

| 方式 | 是否实现 | 优点 | 当前代价 |
| --- | --- | --- | --- |
| BM25 | 是，默认 | 无外部依赖、匹配过程易检查、当前拒绝无支持问题较保守 | 中文字符二元组粗糙；可能漏掉改写问题，短问题也可能无结果 |
| 概念增强 BM25 | 是，可切换 | 通过公开别名表让部分改写问题命中概念 | 会把只在概念上相关、实际不能回答的问题也召回；别名需要维护 |
| 向量检索 | 未实现、未比较 | 候选方向是补充语义改写召回 | 本机未检测到嵌入服务，尚未选定中文嵌入模型；不能声称一定更好 |
| BM25＋向量融合 | 未实现、未比较 | 候选方向是结合词法与语义 | 尚无两路实测结果，先不增加融合、重排和数据库复杂度 |

“概念增强”是词法与元数据规则，不是向量混合检索，也没有训练语义模型。BM25 用中文字符二元组与英文词匹配，概念增强再按命中别名增加概念覆盖分；1.5 的候选门槛和2.5的概念权重是初始启发式，尚未校准。

## 实际诊断结果

同一套 17 个作者编写的问题，其中 13 个有人工指定的相关教材卡、4 个库内没有支持材料。该集不是盲测，也没有独立标注者；不是上线指标。

| 方式 | 13题中前3卡命中 | 前1卡命中 | 4个无支持问题仍返回候选 |
| --- | --- | --- | --- |
| BM25 | 12/13 | 12/13 | 0/4 |
| 概念增强 BM25 | 13/13 | 12/13 | 2/4 |

详细逐题结果见[诊断报告](../reports/retrieval-v0/retrieval.md)。这里的命中仅表示找到至少一张标注相关卡，不保证资料完全支持问题或教学回答正确。

两个明确的误召回例子是“概率论的贝叶斯公式怎么证明”和“聚类算法的收敛性证明”。增强版会因概率或聚类别名找到入门卡，但卡片并未提供证明。保留这些失败案例，不用针对题目追加黑名单把分数做漂亮。

因此 v0 默认使用较保守的 BM25，保留增强版作为对照。结果不能推出 BM25 在所有真实问题上更好；下一步需要其他学习者的真实问法、相关性复核与实际嵌入模型对照。

## 如何运行

在 PowerShell 中进入项目目录：

```powershell
cd D:\codex\创意\ai-learning-tutor
python -m tutor_rag search "分类输出0.7的概率，为什么不叫回归？"
python -m tutor_rag search "买的可能性有七成，这个数怎么拿来做行动规则？" --mode concept-bm25
python -m tutor_rag prompt "分类输出概率为什么不是回归？"
python -m tutor_rag evaluate --out reports/retrieval-v0
python -m unittest discover -s tests -v
```

search 返回教材候选，answer 明确为 null。prompt 仅输出接模型所需的消息，不调用模型。上下文预算按字符而非 Token 计算；超预算时丢弃整卡并报告遗漏，避免从中间截断解释。仍需在选择实际模型后改为其 Token 预算并验证。

## 本轮没有做的事

- 用户确认目前没有模型服务，先看检索原型。没有安装 Ollama、下载8B权重或向第三方模型发送问题。
- 没有实现完整课程状态机、主动诊断、答案忠实度验证、开放回答判分或教学效果验证。
- 不因没有命中就认定全世界没有答案，也不因有命中就认定足以回答。下一步生成端仍需要检查依据覆盖。
- 不把本诊断集称为隐藏验收集；它在公开仓库中，后续正式验收需另备不入检索库的材料。

## 资料与工程参考

教材依据在 [kb/sources.json](../kb/sources.json)，并逐卡保留来源。完整来源策略见[知识与 RAG 方案](knowledge-and-rag.md)。检索后将材料交给生成模型的后续接口可参考 [Hugging Face RAG cookbook](https://huggingface.co/learn/cookbook/en/advanced_rag)；本轮尚未运行其模型或复现其效果。

BM25 的词频饱和与文档长度归一化含义可参考 [Elastic 官方说明](https://www.elastic.co/docs/reference/elasticsearch/index-settings/similarity)。本项目为标准库实现，使用 k1=1.5、b=0.75，不依赖或声称复现 Elasticsearch。

已运行10项自动化测试，覆盖关联卡检索、完整上下文与前置卡、字符预算、来源校验、诊断标注不入库、无生成模型时不伪造答案及CLI输入错误处理。首次测试发现Windows错误输出编码和沙箱临时目录问题，分别统一UTF-8及使用项目内临时目录修复，复测全部通过。
